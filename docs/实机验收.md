# 实机验收

本验收用于证明“鼠标始终连接 Windows，iPad 是独立 Windows 扩展屏”，而不是只证明程序能够启动。采集脚本只读系统状态，默认把结果写入 `reports\safety`。

## 验收前提

- 安装前门禁已经通过，并已生成安装后唯一收据。
- Windows 和 iPad 位于同一可信 5 GHz Private 局域网。
- iPad 上 OpenDisplay 保持前台，监听 TCP `9000`。
- Windows 发送端已连接 iPad；Windows 不应监听 `9000`，应主动建立到 iPad 的出站连接。
- 蓝牙鼠标 `MCHOSE G3 V2 Pro` 仍只连接 Windows，不切换硬件模式。

## 一次性状态采集

连接成功后，在普通 PowerShell 中运行；把示例 IP 换成 iPad 当前局域网 IP：

```powershell
$project = (Resolve-Path '.').Path
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$project\tools\safety\Collect-AcceptanceState.ps1" `
  -IpadAddress '192.168.1.50' `
  -IpadPort 9000 `
  -NetworkInterfaceAlias 'WLAN 2' `
  -BluetoothMouseName 'MCHOSE G3 V2 Pro' `
  -ExpectedDisplayCount 2
```

JSON 报告包含：

- 每个显示器的设备名、主屏标志、坐标和尺寸
- 活动网卡、IP、网络类别和链路速率
- Windows 本地/远端 TCP `9000` 拓扑、所属进程和只读连通性探测
- Windows 蓝牙服务、蓝牙无线电和目标鼠标 PnP 状态
- 发送端进程信息

`OverallPass: true` 要求至少两个显示器、只有一个主屏、网络为 Private、Windows 没有监听 `9000`、iPad 端口可达、目标蓝牙鼠标 Present/OK、蓝牙服务正在运行且发送端进程存在。

## 人工交互验收

状态采集通过后逐项执行并记录结果：

1. Windows“显示设置”选择“扩展这些显示器”，确认 iPad 不是主屏且位于物理屏右侧、顶部对齐。
2. 把一个普通窗口拖入 iPad，再从 iPad 拖回电脑；内容必须是独立桌面而非镜像。
3. 鼠标跨越屏幕边缘往返 200 次，全程不得触碰鼠标模式键；左右键、滚轮和拖拽均需正常。
4. 连续运行 60 分钟，目标为 60 fps；记录画面冻结、花屏、断流和重连次数。
5. iPad 前后台切换、关闭再打开 OpenDisplay、Wi-Fi 断开再连接各 10 次。
6. Windows 锁屏/解锁和睡眠/唤醒各 10 次；每次都确认物理主屏、鼠标和 GameViewer 设备仍正常。
7. 强制结束发送端一次。指针和窗口应可回到物理屏；不得出现黑屏、鼠标失效或 GameViewer 被禁用。

## 0.2.0 多设备与地址变化验收

以下项目需要至少两台运行 OpenDisplay 的 iPad；自动化测试不能替代：

1. 先分别通过 Bonjour 添加两台设备，确认配置中稳定 ID 不同；路由器改变第一台的 DHCP 地址后，不编辑配置，确认 mDNS 在线地址更新且仍连接到同一 `hello.id`。
2. 临时阻断 mDNS，确认最近成功 IPv4 或 Bonjour 主机名仍能恢复；再清除该路径，确认手动地址仍是最后兜底。
3. 关闭优先级第一台的 OpenDisplay，启动自动连接；8 秒目标窗口后应只停止第一目标并连接第二台，任一时刻不得出现两个自动 Wi-Fi 目标。
4. 第二台投屏后让 Wi-Fi 短断再恢复；应优先重连第二台，不得自动跳回第一台。
5. 在设备选择器连续点击同一“连接/切换”，确认按钮显示“正在切换”、旧会话退出后只出现一个新会话，窗口仍可拖动和响应。
6. 验证 Tab、Shift+Tab、Enter、Space、Esc；缩放到 125%/150%/200%，并把窗口缩到最小尺寸后用滚轮/滚动条访问底部设置。
7. 使用长中文名、引号、反斜杠和换行保存/重开；确认名称无截断，损坏主配置时可从 `.bak` 读回。

每个关键阶段都再次运行 `Collect-AcceptanceState.ps1`，保留不同时间戳报告。性能验收需要额外用高帧率相机或专用延迟工具测量；本脚本只证明系统拓扑和连接状态，不把 TCP 可达误报为 60 fps 或低延迟已经达标。

## 失败处理

- GameViewer 的实例、INF、版本、状态或 DLL 哈希有任何变化：停止测试，禁止继续安装或自动清理。
- 出现额外虚拟显示、睡眠唤醒黑屏或发送端退出后显示器残留：先保存报告并执行收据回滚预演。
- 只有预演完全通过时，才能按照《驱动安全与回滚》在管理员 PowerShell 中显式使用 `-Apply`。
- 回滚后重新运行安装前门禁，确认 GameViewer 基线恢复且 Parsec 清零；否则保留现场，不进行批量设备删除。
